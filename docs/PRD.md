## 1. 개요

### 1.1 배경
매일 20개 정도의 할 일을 관리하는 개인용 앱을 만드는 실습 프로젝트입니다.
처음 만든 `todo-app`에 이어, PRD를 새로 기획해 `todo-app2`를 만들고, 그 PRD를 5단계 프롬프트로 나눠 `todo-app3`을 다시 만들었습니다.
세 앱을 모두 GitHub Pages에 배포한 뒤, 테스트로 찾은 버그를 고치고 기능(키워드 자동 분류)과 UI(반응형)를 개선했습니다.

### 1.2 목표
1. 설치 · 로그인 없이 **브라우저에서 바로** 쓰는 할 일 앱.
2. 할 일 **추가 · 수정 · 삭제 · 완료 체크**, **업무 / 개인 / 공부** 분류, **진행률** 보기.
3. 새로고침해도 **데이터 유지** (`localStorage`).
4. **순수 JavaScript**로 기술적으로 단순하게 (프레임워크 · 라이브러리 · 빌드 도구 없음).
5. 세 앱 모두 **공개 주소로 배포**하고, 문서(PRD · TRD · TASKS)와 테스트로 품질을 관리.

### 1.3 범위 밖 (Non-Goals)
- 회원가입 · 로그인 · 기기 간 동기화, 서버 · 데이터베이스
- 마감일 · 알림 · 반복 일정 (다음 버전 후보)
- 외부 AI · 서버를 쓰는 분류 (자동 분류는 앱 안의 키워드 목록만 사용)

## 4. 기능 요구사항

우선순위: **P0** 필수 · **P1** 있으면 좋음 · **P2** 다음 버전

### 4.1 핵심 기능 (세 앱 공통, P0)
| ID | 기능 | 요구사항 |
|---|---|---|
| F1 | 할 일 추가 | Enter 또는 추가 버튼, 앞뒤 공백 제거, 빈 값 거부(입력창 흔들림), 최대 100자, 추가 후 포커스 유지 |
| F2 | 수정 | ✏️ 버튼 · 텍스트 더블클릭으로 제자리 편집, 내용 · 카테고리 변경, Enter 저장 / Esc 취소 / 바깥 클릭 저장, 빈 값이면 원래 내용 유지 |
| F3 | 삭제 | 확인 창 후 삭제 |
| F4 | 완료 체크 | 체크박스로 토글, 완료 항목은 취소선 · 흐린 색 · 목록 아래로 |
| F5 | 카테고리 | 업무 · 개인 · 공부 색상 배지, 전체 / 업무 / 개인 / 공부 탭, 마지막 탭 기억 |
| F6 | 진행률 | 전체 완료 개수 · % · 막대, 카테고리별 진행률, 즉시 갱신 |
| F7 | 저장 | 모든 변경 즉시 `localStorage` 저장, 깨진 데이터에도 오류 없이 빈 목록으로 시작 |
| F8 | 부가 기능 (P1) | 오늘 날짜, 빈 목록 안내, 완료 항목 일괄 삭제, 모두 완료 시 🎉 |

### 4.2 키워드 자동 분류 (todo-app2 · todo-app3, P1, 세션 중 추가)
| ID | 요구사항 |
|---|---|
| F9-1 | 할 일을 입력할 때마다 내용 속 키워드로 카테고리를 자동 선택하고 `🤖 자동 분류: 공부`처럼 알려 준다 |
| F9-2 | 키워드는 대소문자 무시, 단어 일부로 들어 있어도 인정 ("보고서를", "헬스장") |
| F9-3 | 여러 카테고리 키워드가 있으면 가장 많이 일치한 쪽, **동점이면 바꾸지 않음** |
| F9-4 | 키워드가 없으면 사용자가 마지막으로 고른(또는 마지막에 쓴) 카테고리 유지 |
| F9-5 | **입력할 때마다 항상** 적용 — 직접 고른 값은 다음 입력 전까지만 유지 (입력 후 직접 고르고 Enter → 그 카테고리로 추가) |
| F9-6 | 수정 중에는 자동 분류하지 않음, 서버 · 외부 AI 사용 안 함 |

> **요구사항 변경 이력:** 처음에는 "사용자가 직접 고르면 그 할 일을 추가할 때까지 자동 분류를 멈춤"으로 정했으나,
> 사용자 피드백("자동 분류가 2회로 제한되어 있나? 입력시마다 적용해")으로 **입력할 때마다 항상 적용**으로 바꿨다 (F9-5).

### 4.3 화면 · 사용성 (세 앱 공통, 세션 중 추가)
| ID | 요구사항 |
|---|---|
| U1 | 320 ~ 1280px 어느 폭에서도 가로 스크롤 · 화면 밖으로 넘치는 요소 없음 (편집 중 포함) |
| U2 | 480px 이하에서 목록 항목은 배지를 위, 내용을 아래에 두어 내용 칸을 넓게 |
| U3 | 480px 이하에서 필터 탭 4개가 한 줄에 모두 보임 |
| U4 | 모든 터치 대상(버튼 · 탭 · 체크박스 누르는 영역) 40px 이상 |
| U5 | 입력창 · 선택 상자 글자 16px 이상 (iPhone에서 누를 때 화면 확대 방지) |
| U6 | 편집 중에 다른 항목의 체크박스 · 버튼 · 필터 탭을 눌러도 편집이 저장되고 누른 동작도 실행됨 |
| U7 | 아이콘은 컬러 이모지로 선명하게 (🗑️), 콘솔 오류 · 404 없음 (파비콘 포함) |

### 4.4 배포 · 문서 (P0)
| ID | 요구사항 |
|---|---|
| D1 | `main`에 push하면 세 앱이 자동 배포: `todo-app`은 사이트 루트, `todo-app2` · `todo-app3`는 하위 경로 |
| D2 | 기획 문서(`*.md`)는 배포하지 않음 |
| D3 | 앱마다 PRD → TRD → TASKS 순서로 문서를 갖추고, 기능을 바꾸면 문서도 함께 갱신 |
| D4 | README에 세 앱 배포 주소 · 문서 링크를 한 표로 정리 |
| D5 | 저장소 안내 문서 `CLAUDE.md` 유지 (명령어 · 구조 · 작업 규칙) |
