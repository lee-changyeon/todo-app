# PROMPTS: PRD로 할 일 앱을 만드는 5단계 프롬프트

| 항목 | 내용 |
|---|---|
| 기준 문서 | [PRD.md](PRD.md) v1.0 |
| 작성일 | 2026-11-11 |
| 사용법 | 아래 프롬프트를 **순서대로 하나씩** Claude Code에 입력한다. 한 단계가 끝나고 결과를 확인한 뒤 다음 단계로 넘어간다. |

> `{폴더}`는 앱을 만들 폴더 이름으로 바꿔서 입력합니다 (예: `todo-app3`).
> 같은 주소에서 다른 할 일 앱과 함께 실행한다면 저장 키도 겹치지 않게 바꿉니다 (예: `todos3`, `todos3Filter`).

| 단계 | 목표 | 관련 PRD |
|---|---|---|
| 1 | 화면 뼈대와 기본 스타일 | 5장 화면 구성, 6장 기술 요구사항 |
| 2 | 데이터 저장과 추가 · 삭제 · 완료 체크 | F1, F3, F4, F7, 4장 데이터 모델 |
| 3 | 수정과 카테고리 | F2, F5 |
| 4 | 필터 탭 · 진행률 · 부가 기능 | F5, F6, F8 |
| 5 | 수용 기준 테스트와 마무리 | 7장 수용 기준 |

---

## 1단계. 화면 뼈대와 기본 스타일

```
PRD.md를 읽고 {폴더}/ 에 할 일 앱의 화면 뼈대를 만들어줘.

- 파일은 index.html, style.css, app.js 3개만 쓰고, 프레임워크·라이브러리·빌드 도구는 쓰지 마.
- PRD 5장 화면 구성 순서대로 만들어: 제목과 오늘 날짜 → 진행률 영역(텍스트, 프로그레스 바, 카테고리별 진행률)
  → 추가 폼(입력창, 카테고리 선택, 추가 버튼) → 필터 탭 → 할 일 목록 → 빈 목록 안내 → "완료 항목 지우기" 버튼.
- 목록·필터 탭·카테고리별 진행률처럼 데이터로 그릴 부분은 빈 컨테이너로 두고, JS가 찾을 수 있게 id를 붙여.
- 입력창은 maxlength 100, 아이콘 버튼과 입력 요소에는 aria-label을 붙여.
- style.css는 색을 CSS 변수로 정의하고(업무 파랑·개인 초록·공부 보라 포함), 최대 폭 640px 카드 레이아웃,
  360px 화면에서도 가로 스크롤이 생기지 않게 반응형으로 만들어.
- app.js는 </body> 직전에 불러오도록 연결만 해 둬.
```

**확인:** `index.html`을 브라우저로 열었을 때 PRD 5장 스케치와 같은 배치가 보이는지.

## 2단계. 데이터 저장과 추가 · 삭제 · 완료 체크

```
{폴더}/app.js 에 할 일의 상태 관리와 기본 기능을 구현해줘.

- 데이터 모델은 PRD 4.1 Todo 객체(id, text, category, completed, createdAt)를 따르고,
  저장 키는 PRD 4.2를 따라 (다른 앱과 겹치면 키 이름을 바꿔).
- 카테고리 상수(업무 work · 개인 personal · 공부 study)를 이 단계에서 정의하고,
  추가 폼의 카테고리 선택 상자를 그 상수로 채워 (추가할 때 카테고리가 필요하므로). 배지와 수정은 3단계에서 한다.
- 구조는 "이벤트 → 상태 변경 함수 → commit()" 한 방향으로 만들고, commit()은 save() 후 render()를 호출해.
  화면은 항상 todos 배열로부터 새로 그리고, DOM에 상태를 따로 두지 마.
- 불러올 때 JSON이 깨졌거나 형식이 잘못된 항목은 걸러서, 오류 없이 빈 목록으로 시작하게 해 (F7).
- 할 일 추가 (F1): trim, 빈 값이면 추가하지 말고 입력창을 흔들어 알려 줘. 추가 후 입력창을 비우고 포커스 유지.
- 삭제 (F3): 확인 창을 띄운 뒤 삭제.
- 완료 체크 (F4): 체크박스로 토글, 완료 항목은 취소선·흐린 색으로 목록 아래로 정렬.
- 목록 클릭은 #목록 컨테이너 하나에 이벤트 위임으로 처리하고 data-action으로 동작을 구분해.
- 사용자 입력은 textContent로만 출력해 (innerHTML 금지).
```

**확인:** 추가 · 체크 · 삭제가 되고, 새로고침해도 목록이 남는지.

## 3단계. 수정과 카테고리

```
{폴더}/ 에 PRD F2(수정)와 F5(카테고리 배지)를 구현해줘.

- 2단계에서 정의한 카테고리 상수 하나를 추가 폼의 선택 상자, 배지, 편집용 선택 상자, 데이터 검증에 모두 쓰게 해.
- 각 항목에 카테고리 색상 배지를 표시해.
- 수정: ✏️ 버튼 클릭 또는 텍스트 더블클릭으로 그 자리에서 편집 모드로 바꾸고, 내용과 카테고리를 함께 고칠 수 있게 해.
- Enter = 저장, Esc = 취소, 편집 항목 밖을 클릭하면 저장.
  단, 같은 항목 안에서 입력창 ↔ 카테고리 선택으로 포커스가 옮겨 갈 때는 편집이 끝나지 않게 해.
- 빈 값으로 저장하면 원래 내용을 유지해.
```

**확인:** ✏️ / 더블클릭으로 수정되고 Enter · Esc · 바깥 클릭이 PRD대로 동작하는지.

## 4단계. 필터 탭 · 진행률 · 부가 기능

```
{폴더}/ 에 PRD F5(필터 탭), F6(진행률), F8(부가 기능)을 구현해줘.

- 필터 탭: 전체 / 업무 / 개인 / 공부, 탭마다 항목 개수 표시, 선택한 탭을 저장해서 새로고침 후에도 유지.
- 진행률: 전체는 "완료 3 / 8 (38%)" 형식과 프로그레스 바, 그 아래 카테고리별 "업무 2/4 (50%)" 표시.
  0개일 때는 0%로 처리하고, 추가·체크·삭제 즉시 갱신해.
- 부가 기능: 오늘 날짜 표시, 빈 목록 안내 문구, 완료 항목 일괄 삭제(확인 창, 완료 0개면 버튼 비활성),
  모두 완료하면 🎉 표시.
- 진행률 바에는 role="progressbar"와 aria-valuenow를 넣어.
```

**확인:** 탭 전환 · 진행률 숫자와 막대 · 🎉 표시가 맞는지.

## 5단계. 수용 기준 테스트와 마무리

```
{폴더}/ 의 앱을 PRD 7장 수용 기준 AC-01 ~ AC-13으로 테스트해줘.

- 브라우저에서 실제로 실행해서 확인하고, 시나리오마다 통과/실패를 표로 정리해.
- 깨진 JSON(AC-10), 할 일 20개 이상(AC-11), 360px 화면(AC-12), 콘솔 오류(AC-13)도 빠짐없이 확인해.
- 실패한 항목은 원인을 찾아 고치고 다시 테스트해.
- 마지막으로 무엇을 고쳤는지와 최종 결과를 알려줘.
```

**확인:** 모든 수용 기준이 통과로 정리됐는지.
